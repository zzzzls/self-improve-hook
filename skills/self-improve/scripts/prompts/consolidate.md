## 输出格式

直接输出 markdown 全文,不要加任何解释、不要包 ```markdown 围栏。

模板:

```markdown
# 项目记忆(自动生成)

> 由经验提取流水线维护。最后更新:<ISO_TIMESTAMP>

## 用户长期指令
- ...

- ...

- ...

## 工具使用偏好
- ...

## 工作流约定
- ...

## 问题修正
- ...
```

`<ISO_TIMESTAMP>` 用占位符 `__UPDATED_AT__`,合并程序会替换。

## 合并规则(按优先级)

1. **章节固定 6 个**,严格按上面模板的标题与顺序。type → 章节映射:
   - `user_instruction` → 用户长期指令
   - `project_convention` → 项目约定
   - `error_lesson` → 错误经验
   - `tool_preference` → 工具使用偏好
   - `workflow_convention` → 工作流约定
   - `issue_fix` → 问题修正

2. **语义去重**:若一条新候选和一条现有规则表达相同意思,**用新的替换旧的**(以最新为准)。判断"相同意思"以语义为准,不仅看字面。

3. **冲突处理**:若新规则与现有规则**矛盾**(例如旧的说"用 tab",新的说"用 2 空格"),**保留新的,删除旧的**。

4. **合并相似项**:若多条规则可以合并成一条更精确的表达,合并之;但不要为了合并丢失关键约束。

5. **每条规则一行**:用无序列表 `- `,结尾不加句号也可,但**全文统一**。

6. **空章节也保留标题**,内容写 `(暂无)`,不要删除章节。

7. **去除明显违规内容**:若候选里出现密钥、token、IP 等,静默丢弃,不要进入输出。

8. **保持稳定**:与现有 memory.generated.md 内容相比,**不要无故重写已经稳定的句子**;只动需要改的部分。
